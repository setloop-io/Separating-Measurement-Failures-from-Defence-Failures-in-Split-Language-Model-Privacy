**Bottom line:** we are not close to an empirical publication. The repository has a strong protocol and evidence foundation, but R1 has no scientific implementation, execution, or result. The first decision is the publication track.

## Real backlog and serial critical path

1. **Choose the paper type and venue.**
   - AI/privacy paper: retain the logical single-process split and explicitly exclude deployed transport.
   - Systems paper: implement a real trusted-client/remote-service boundary before paid experiments.
   - Recommendation: if systems contribution is the goal, do not benchmark the current whole-model-on-remote runner as if it were split execution.

2. **Close engineering-validity gaps.**
   - Replace mock-only end-to-end validation with a real bounded training integration test.
   - Semantically validate checkpoints, captures, inventories, shapes and dtypes—not only hashes.
   - Distinguish failed/interrupted/not-started runs.
   - Fix retry attempt identities and verify all-local common-component initialization from retained evidence.

3. **Bind the remote environment and budget.**
   - Select provider/GPU/image; lock dependencies and container digest.
   - Add provider-side lifetime/spend shutdown.
   - Approve one engineering budget.
   - Run 14 micro checks, then the separate 4-run performance calibration.
   - Stop if CUDA, provenance, semantic artifacts, memory, output size or cost checks fail.

4. **Implement the scientific stack.**
   - Four-region data-panel loader.
   - Full-precision forward, returned-value and two-gradient captures.
   - Final model, optimizer and RNG checkpoints.
   - Twelve target/channel attack combinations, target-model fitting, matched nulls and positive controls.
   - Analysis with three-valued pass/reject/undetermined logic.

5. **Freeze and run calibration.**
   - Review and externally timestamp the calibration packet before scores are inspected.
   - Run 76 calibration models.
   - Qualify each target/channel/defense independently.
   - If required attacks fail qualification, amend prospectively or leave affected privacy outcomes undetermined.

6. **Freeze and run exploration.**
   - Freeze the revised 19-cell protocol after calibration decisions.
   - Run all 232 planned models and preserve every failure.
   - Report continuous utility, gain-over-frozen, gain-over-removal and qualified privacy results.
   - Undetermined cells prevent an empty-set claim unless another valid gate rejects them.

7. **Design and execute confirmation.**
   - Predeclare candidate selection, sample size, multiplicity and endpoints.
   - Externally timestamp the confirmation protocol.
   - Use the untouched reserved seeds; exploration results cannot become confirmation.

8. **Produce the empirical paper.**
   - Update the claim ledger only from admitted evidence.
   - Generate all tables/figures from machine-readable results.
   - Run independent statistical, privacy, artifact and PDF audits.
   - Publish a fresh-checkout evidence package, submit, then address venue review.
