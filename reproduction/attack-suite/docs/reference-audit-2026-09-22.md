## Initial link policy and history cleanup (superseded)

At the initial audit snapshot, both papers linked through GitHub/Hugging Face `main` and omit explicit source/model commit identifiers. Named release directories and SHA-256 content manifests identify the evaluated data and archived execution source. “Latest code” is the current reader-facing reference; it is not retroactively asserted to have produced old experiments.

The initial repository scan found commit-related text in 567 tracked files (712 matching lines): 487 result files, 43 experiment files, 30 documentation files, three paper files, two tests, one attack source file and README. This is a lower bound: archived binaries/source tarballs were not unpacked. These include executable source guards and sealed evidence records, so replacing every hash with `main` would break validation or misrepresent provenance.

The initial changes removed commit-specific references from both manuscripts and the main reader-facing entry points. Historical audit documents, protocols, result records and archived evidence are retained pending the requested file-retention decision. No GitHub or Hugging Face history has been deleted. No experimental reference was rebased or relabelled.

A complete public-history reset requires deciding whether to retain those historical evidence files, preserving an offline backup, preparing a clean final tree, checking all content manifests and links, publishing the final manuscripts, then resetting the remote histories/refs. A GitHub main-branch reset alone leaves other branches/tags and cached or forked copies; a Hugging Face history squash retains all files in its current tree. These are distinct from deleting the historical evidence files themselves.
